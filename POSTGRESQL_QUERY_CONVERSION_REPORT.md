## Work completed in this continuation

### Authentication

The PostgreSQL authentication route was already PostgreSQL-native; this continuation did not rewrite its SQL. Its 12 inventoried query/adapter call sites remain explicitly certified by the isolated Neon API integration. That test exercises registration, duplicate/invalid credentials, customer/vendor login, session management, `/me`, role redirect, registration notifications/history, vendor profile upsert, and transaction rollback.

### Customer account profile and password

Added [postgresCustomerAccount.js](./backend/src/routes/postgresCustomerAccount.js) and mounted it only in PostgreSQL mode. The PostgreSQL routes implement profile read/update and password change for customer/organizer accounts. Profile changes and password changes are audited; password changes lock the account row, verify the existing password, update the hash, invalidate other user sessions, and preserve the active session. The legacy MySQL customer route was not changed.

Six SQL call sites in the new route are marked certified only after the isolated Neon integration exercised profile update/audit and password lookup/update/session invalidation/audit, including invalid input, incorrect current password, successful subsequent login with the new password, and rejection of the old password.
